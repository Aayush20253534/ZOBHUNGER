# Phase 7 — Production Email Delivery

Phase 7 standardizes ZOBHUNGER transactional and operational email on the existing Resend provider. WhatsApp is intentionally outside this phase.

## Production environment

Required by the existing production guard:

```env
RESEND_API_KEY=re_...
MAIL_FROM_EMAIL=notifications@zobhungr.com
MAIL_FROM_NAME=ZOBHUNGER
SALES_TEAM_EMAIL=operations@zobhungr.com
```

Recommended routing configuration:

```env
MAIL_REPLY_TO_EMAIL=help@zobhungr.com
HR_TEAM_EMAIL=hr@zobhungr.com
TECH_TEAM_EMAIL=tech@zobhungr.com
PLACEMENT_TEAM_EMAIL=placementcell@zobhungr.com
LEGAL_TEAM_EMAIL=legal@zobhungr.com
RESEND_TIMEOUT_MS=15000
```

The `MAIL_FROM_EMAIL` domain must be verified in Resend before production sending. Department addresses are recipients/reply paths and may be changed without rebuilding the client.

## Email flows

Phase 7 provides branded HTML + text messages for:

- Website enquiry acknowledgement and department alert
- Workforce requirement acknowledgement and status updates
- Public, Worker Portal and Placement Cell job application acknowledgements
- Hiring-team application status updates
- Business partner application acknowledgement, review updates and approved account credentials
- Institution partnership acknowledgement, review updates and secure activation
- Career profile acknowledgement and HR status updates
- Vendor empanelment acknowledgement and review updates
- Employee joining acknowledgement, HR status updates and signed offer-letter delivery
- Worker email verification and password reset
- Business password recovery
- Department administrator invitations
- Intake case assignment alerts

## Department routing

| Intake / workflow | Internal recipient |
| --- | --- |
| HR / career / employee / normal hiring | `HR_TEAM_EMAIL` |
| Website & App Development enquiries | `TECH_TEAM_EMAIL` |
| Placement Cell / institution workflows | `PLACEMENT_TEAM_EMAIL` |
| Legal / privacy / compliance enquiries | `LEGAL_TEAM_EMAIL` |
| General business, workforce, partner and vendor workflows | `SALES_TEAM_EMAIL` |

Main Administration still sees the operational records in the Admin Portal regardless of which inbox receives the alert.

## Reliability and privacy

- Resend idempotency keys are supplied for receipts, status updates, invitations, credentials and offer letters.
- Provider errors are logged through sanitized diagnostics without logging email bodies, access tokens, temporary passwords or recipients.
- A provider failure does not reverse an already-committed form/admin database update for ordinary notifications.
- Employee joining notifications deliberately exclude Aadhaar, PAN, bank-account, UAN and uploaded document contents.
- Offer letters remain protected PDF attachments generated by the existing HR workflow.
- Every branded message includes a plain-text alternative.

## Validation

Run:

```powershell
npm run test:email-production
npm --prefix server run check:email
npm run verify
```

`check:email` uses Resend's safe provider test recipient. A successful provider check confirms Resend accepted the message; it does not guarantee delivery to every real mailbox.
